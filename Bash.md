# Мой конспект по Bash

Это мои заметки для подготовки на DevOps. Пишу простыми словами, но так, чтобы это можно было почти дословно сказать на собесе. В каждой теме: **как я это понимаю** (для себя, простыми словами) и **что говорю на собесе** (коротко и правильно). Все команды проверяю в своём Debian. Базу про потоки, пайпы и окружение я держу в конспекте по Linux, здесь иду глубже в сам язык.

## 1. Что такое bash и как запускается скрипт

**Как я это понимаю.** **Shell (оболочка)** это программа, которая читает мои команды и запускает их. **Bash** это самая распространённая оболочка в Linux. Скрипт это обычный текстовый файл с командами, которые bash выполняет по порядку. В Debian `/bin/sh` это **dash**: быстрее, но без bash-расширений (`[[ ]]`, массивы, `${var^^}`), поэтому скрипты с такими фишками начинаю с `#!/bin/bash`.

**Shebang** (первая строка) говорит системе, чем запускать файл:

| Строка | Смысл |
|---|---|
| `#!/bin/bash` | Запускать этим bash (путь фиксирован) |
| `#!/usr/bin/env bash` | Найти bash в `PATH` (переносимее, если bash лежит не в `/bin`) |
| `#!/bin/sh` | Запускать sh (в Debian это dash), только POSIX-синтаксис |

**Способы запуска:**

| Как | Что происходит |
|---|---|
| `./script.sh` | Новый процесс, нужен бит `x` (`chmod +x`), интерпретатор берётся из shebang. Переменные скрипта наружу не попадают |
| `bash script.sh` | Новый процесс, бит `x` не нужен, shebang игнорируется |
| `source script.sh` или `. script.sh` | Выполняется **в текущей оболочке**: переменные, функции и смена папки остаются. Так подключают файлы с окружением и библиотеки функций |

**Что говорю на собесе.** `./script.sh` и `source script.sh` отличаются тем, где выполняются: первый создаёт дочерний процесс (родителю его переменные недоступны), второй работает в текущей оболочке.

**Как bash находит команду:** сначала псевдоним (alias, только в интерактивной оболочке), потом функция, потом встроенная команда (builtin, например `cd`, `echo`, `read`), потом программа из `PATH`. Увидеть, что именно запустится: `type -a имя`. Псевдонимы в скриптах по умолчанию не раскрываются.

```bash
type -a echo        # echo is a shell builtin, echo is /usr/bin/echo
help cd             # справка по встроенной команде
chmod +x script.sh && ./script.sh
bash -n script.sh   # проверить синтаксис, не запуская
```

Каждая команда завершается с **кодом возврата**: 0 это успех, всё остальное ошибка. Он лежит в `$?` и управляет условиями и циклами (раздел 8).

## 2. Переменные и подстановка параметров

**Как я это понимаю.** Переменная это имя со значением. Присваиваю без пробелов вокруг `=`, читаю через `$`. Значения в bash по умолчанию строки. Если нужны числа, считаю через `$(( ))`.

```bash
name="мир"                 # присвоить (без пробелов вокруг =)
echo "Привет, $name"       # прочитать (в двойных кавычках)
echo "${name}_backup"      # фигурные скобки отделяют имя от соседнего текста
readonly PI=3.14           # константа
unset name                 # удалить переменную
export VAR=значение        # передать дочерним процессам
```

- **Область видимости:** переменная в скрипте глобальная. Внутри функции `local x=1` делает её локальной.
- **Окружение:** обычная переменная видна только текущей оболочке, `export` передаёт копию дочерним процессам. Изменить окружение родителя из дочернего процесса нельзя.

**Подстановка параметров** (то, что экономит вызовы `sed` и `cut`):

| Запись | Что делает |
|---|---|
| `${var:-default}` | Значение `var`, а если не задана или пустая, то `default` |
| `${var:=default}` | То же, но ещё и присвоить `default` |
| `${var:?сообщение}` | Если не задана или пустая, вывести сообщение и завершить скрипт |
| `${var:+значение}` | Если задана и не пуста, то `значение`, иначе пусто |
| `${#var}` | Длина строки |
| `${var:2:5}` | Подстрока: с 2-го символа, 5 штук |
| `${var#шаблон}`, `${var##шаблон}` | Убрать **с начала** кратчайшее (`#`) / длиннейшее (`##`) совпадение |
| `${var%шаблон}`, `${var%%шаблон}` | Убрать **с конца** кратчайшее (`%`) / длиннейшее (`%%`) совпадение |
| `${var/старое/новое}`, `${var//старое/новое}` | Заменить первое / все вхождения |
| `${var^^}`, `${var,,}` | В верхний / нижний регистр (bash 4 и новее) |

Пример на файле:

```bash
f="backup.tar.gz"
echo "${f%.gz}"      # backup.tar     (убрать расширение с конца)
echo "${f%%.*}"      # backup         (убрать всё после первой точки)
echo "${f#*.}"       # tar.gz         (убрать имя до первой точки)
echo "${f##*.}"      # gz             (расширение)
echo "${f/tar/zip}"  # backup.zip.gz
echo "${#f}"         # 13
```

**Что говорю на собесе.** Для значений по умолчанию использую `${var:-default}`, для обязательных параметров `${var:?сообщение}`: скрипт упадёт сразу с понятной ошибкой, а не пойдёт дальше с пустой переменной (например, `rm -rf "$dir/"` при пустом `dir` стёр бы корень).

## 3. Кавычки, раскрытия и подстановки

**Как я это понимаю.** Перед запуском команды bash «раскрывает» строку: подставляет переменные, команды, шаблоны файлов. Кавычки управляют тем, что раскрывать, а что оставить как есть. Самая частая ошибка новичка это переменная **без кавычек**: bash режет её значение по пробелам (word splitting) и раскрывает `*` (globbing).

| Вид | Что делает |
|---|---|
| `'...'` | Всё как текст, ничего не раскрывается |
| `"..."` | Подставляются переменные, `$(...)`, арифметика; пробелы внутри не режут слово |
| без кавычек | Раскрывается всё, значение режется по пробелам и по `*` |

```bash
file="my file.txt"
rm $file            # ОШИБКА: удалит два файла, «my» и «file.txt»
rm "$file"          # верно: один файл
```

Правило: **переменные всегда в двойных кавычках**, кроме случаев, когда нужно именно раскрытие.

**Виды раскрытий (в порядке применения):**

| Что | Пример | Результат |
|---|---|---|
| Фигурные скобки | `echo file{1,2,3}.txt`, `mkdir -p proj/{src,docs}`, `echo {1..5}` | Список вариантов (делается **до** подстановки переменных, поэтому `{1..$n}` не работает, нужен `seq` или цикл) |
| Тильда | `~`, `~user` | Домашняя папка |
| Параметры | `$var`, `${var}` | Значение переменной |
| Команда | `$(date +%F)` | Вывод команды (старый вариант с обратными кавычками `` `date` `` хуже: вложенность и экранирование) |
| Арифметика | `$((a + b * 2))` | Результат (только целые числа) |
| Шаблоны файлов (glob) | `*.log`, `file?.txt`, `[abc]*` | Список подходящих файлов |

**Glob и regex это разные вещи:** `*` в glob значит «любые символы» в имени файла, а в регулярном выражении это «повтор предыдущего». Если файлов по шаблону нет, bash оставляет сам шаблон как текст (меняется через `shopt -s nullglob`). Скрытые файлы (`.имя`) `*` не захватывает (меняется через `shopt -s dotglob`).

**Арифметика:**

```bash
a=5; b=3
echo $((a + b))        # 8
(( a > b )) && echo "a больше"
(( count += 1 ))
```

Только целые числа. Для дробных использую `awk` или `bc`.

**Подстановка процесса** `<(команда)` даёт вывод команды как временный файл:

```bash
diff <(sort a.txt) <(sort b.txt)     # сравнить два отсортированных потока
while read -r line; do echo "$line"; done < <(ls)   # цикл в текущей оболочке, а не в подоболочке
```

**Here-document и here-string:**

```bash
# переменные раскрываются
cat <<EOF
Привет, $USER
EOF

# в кавычках раскрытия нет, текст как есть
cat <<'EOF'
Привет, $USER
EOF

grep -c error <<< "$text"         # here-string: строка как stdin
```

Всё, что написано между `<<EOF` и `EOF`, это текст, включая комментарии. Поэтому пояснения ставлю снаружи.

`<<-EOF` убирает ведущие табуляции (удобно с отступами внутри функций).

## 4. Аргументы и ввод

**Как я это понимаю.** Скрипт получает то, что я написал после его имени. Это его аргументы.

| Переменная | Значение |
|---|---|
| `$0` | Имя скрипта |
| `$1`, `$2` ... `${10}` | Аргументы по номерам (с десятого скобки обязательны) |
| `$#` | Сколько аргументов |
| `"$@"` | Все аргументы **по отдельности** (границы сохраняются) |
| `"$*"` | Все аргументы **одной строкой** (через первый символ `IFS`) |
| `$?` | Код возврата последней команды |
| `$$` | PID самого скрипта |
| `$!` | PID последнего фонового процесса |

Почти всегда нужен `"$@"` в кавычках: передать аргументы дальше без потери пробелов.

```bash
#!/usr/bin/env bash
set -euo pipefail

usage() { echo "Использование: $0 <файл> [<количество>]" >&2; exit 2; }

[[ $# -ge 1 ]] || usage            # проверить число аргументов
file=$1
count=${2:-10}                     # значение по умолчанию
shift                              # убрать первый аргумент из списка
```

**Опции через `getopts`** (короткие флаги вида `-v -d путь`):

```bash
verbose=0
while getopts ":hvd:" opt; do
  case $opt in
    h) usage ;;
    v) verbose=1 ;;
    d) dir=$OPTARG ;;
    :) echo "Для -$OPTARG нужен аргумент" >&2; exit 2 ;;
    \?) echo "Неизвестная опция -$OPTARG" >&2; exit 2 ;;
  esac
done
shift $((OPTIND - 1))              # после этого $1 это первый обычный аргумент
```

`getopts` понимает только короткие опции (`-v`). Длинные (`--verbose`) разбираю вручную через `case`.

**Чтение ввода (`read`):**

```bash
read -r -p "Продолжить? [y/N] " answer      # спросить пользователя
read -r -s -p "Пароль: " pass               # без вывода символов
read -r -t 5 line || echo "таймаут"         # с ограничением по времени

while IFS= read -r line; do                 # прочитать файл построчно
  echo "строка: $line"
done < file.txt
```

`-r` отключает обработку обратных слэшей (без него `\` съедается), `IFS=` сохраняет пробелы по краям строки.

## 5. Условия

**Как я это понимаю.** Условие в bash это **команда**, и важен её код возврата: 0 значит «истина», не 0 значит «ложь».

```bash
if grep -q error file.log; then       # условие: код возврата grep
  echo "ошибки есть"
elif [[ -s file.log ]]; then
  echo "файл не пустой, ошибок нет"
else
  echo "файл пустой"
fi
```

**`[ ]` и `[[ ]]`: в чём разница (частый вопрос):**

| | `[ ... ]` | `[[ ... ]]` |
|---|---|---|
| Что это | Команда `test` (есть в POSIX, работает и в dash) | Ключевое слово bash (в dash нет) |
| Пустая или с пробелами переменная | Нужны кавычки, иначе ошибка | Безопаснее, раскрытия слов нет |
| `&&`, `\|\|` внутри | Нет (только `-a`, `-o`, они устарели) | Есть |
| Сравнение с шаблоном (`==`) и регулярка (`=~`) | Нет | Есть |

В bash-скриптах я использую `[[ ]]`, в `/bin/sh` приходится `[ ]`.

**Проверки файлов:**

| Проверка | Значит |
|---|---|
| `-e` | Существует |
| `-f` | Обычный файл |
| `-d` | Папка |
| `-L` | Символическая ссылка |
| `-r`, `-w`, `-x` | Можно читать, писать, запускать |
| `-s` | Существует и **не пустой** |

**Проверки строк и чисел:**

| Что | Запись |
|---|---|
| Строка пустая / не пустая | `-z "$s"` / `-n "$s"` |
| Строки равны / не равны | `"$a" == "$b"` / `"$a" != "$b"` |
| Совпадает с шаблоном | `[[ $f == *.log ]]` (справа без кавычек) |
| Совпадает с регуляркой | `[[ $s =~ ^[0-9]+$ ]]` (группы в `${BASH_REMATCH[1]}`) |
| Числа | `-eq` `-ne` `-lt` `-le` `-gt` `-ge` или `(( a > b ))` |

Строки сравниваю `==`, числа `-eq` или `(( ))`. Для чисел нельзя использовать `>` внутри `[[ ]]`: он сравнивает строки (`"10" < "9"`).

**Комбинации:**

```bash
[[ -f $file && -r $file ]] && echo "файл читается"
[[ $x == a || $x == b ]]
! grep -q foo file && echo "foo нет"

cmd1 && cmd2          # cmd2 только если cmd1 успешна
cmd1 || cmd2          # cmd2 только если cmd1 упала
```

Осторожно: `cmd1 && cmd2 || cmd3` это **не** `if/else`: если `cmd2` упадёт, выполнится `cmd3`.

**`case`** это выбор по шаблону, удобен для разбора действий и опций:

```bash
case $1 in
  start)        echo "запуск" ;;
  stop|restart) echo "остановка" ;;
  *.log)        echo "это лог" ;;
  *)            echo "неизвестно: $1" >&2; exit 2 ;;
esac
```

## 6. Циклы

```bash
for name in alice bob carol; do echo "$name"; done     # по списку

for f in *.log; do                                     # по файлам (шаблон, а не ls!)
  [[ -e $f ]] || continue
  echo "обрабатываю $f"
done

for ((i = 1; i <= 5; i++)); do echo "$i"; done         # в стиле C
for i in {1..5}; do echo "$i"; done                    # диапазон (числа константой)

n=0
while (( n < 3 )); do echo "$n"; n=$((n + 1)); done        # пока условие истинно
until ping -c1 -W1 host &>/dev/null; do sleep 1; done  # пока условие ложно
```

- `break` выходит из цикла, `continue` переходит к следующему шагу.
- **Цикл по файлам** делаю через шаблон (`for f in *.log`), а не через `for f in $(ls)`: второй ломается на пробелах в именах.
- **Построчное чтение** `while IFS= read -r line; do ... done < файл`.
- **Цикл с повтором** (retry): пробую несколько раз с паузой (пример в разделе 14).

## 7. Функции

**Как я это понимаю.** Функция это именованный блок команд, который вызывается как обычная команда. Она нужна, чтобы не дублировать код и держать скрипт читаемым.

```bash
log() {                                  # вывод с временем в stderr
  local level=$1; shift
  printf '%s [%s] %s\n' "$(date '+%F %T')" "$level" "$*" >&2
}

is_root() { [[ $EUID -eq 0 ]]; }         # результат функции = код возврата последней команды

add() {
  local a=$1 b=$2
  echo $((a + b))                        # «вернуть значение» = напечатать
}

sum=$(add 2 3)                           # поймать вывод в переменную
is_root || log ERROR "нужен root"
```

- Аргументы функции это `$1`, `$2`, `$@` (свои, не скрипта).
- **`return n`** возвращает **код** (число от 0 до 255), а не значение. Данные «возвращают» через `echo` и ловят через `$(...)`.
- Переменные в функции глобальные, пока не объявлены через `local`. **`local` обязателен**, иначе функция портит чужие переменные.
- Шаблон структуры скрипта: функции сверху, внизу `main "$@"`.

```bash
main() {
  # вся логика
  :
}
main "$@"
```

## 8. Коды возврата и обработка ошибок

**Как я это понимаю.** Каждая команда завершается числом от 0 до 255. **0 это успех, любое другое число ошибка.** Код последней команды лежит в `$?`. Условия, `&&`, `||`, `set -e` работают именно с кодами.

| Код | Значение |
|---|---|
| 0 | Успех |
| 1 | Общая ошибка |
| 2 | Неверное использование (аргументы, синтаксис), удобно использовать для `usage` |
| 124 | `timeout` оборвал команду |
| 126 | Команда найдена, но не исполняемая (нет права `x`) |
| 127 | Команда не найдена (`command not found`) |
| 128 + N | Процесс убит сигналом N: **130** это Ctrl+C (SIGINT), **137** это SIGKILL (в контейнерах часто OOM Killer), **143** это SIGTERM |
| 141 | SIGPIPE (128 + 13): читающая сторона пайпа закрылась раньше |

`exit N` завершает скрипт с кодом N, `return N` выходит из функции. `exit` без числа вернёт код последней команды.

**Строгий режим** (в начало каждого скрипта):

```bash
#!/usr/bin/env bash
set -euo pipefail
```

| Флаг | Что делает |
|---|---|
| `-e` | Завершить скрипт, если команда вернула ошибку |
| `-u` | Ошибка при обращении к необъявленной переменной |
| `-o pipefail` | Пайп считается неуспешным, если упало **любое** звено, а не только последнее |

**Подводные камни `set -e`** (то, чем хвастаются на собесах):

- Не срабатывает в условиях: `if cmd`, `cmd || ...`, `cmd && ...` (кроме последней в цепочке), `! cmd`, `while cmd`.
- `local x=$(cmd)` скрывает код возврата `cmd` (код возвращает сам `local`). Объявляю и присваиваю отдельно: `local x; x=$(cmd)`.
- `(( count++ ))` при `count=0` возвращает 1 (значение выражения 0 считается «ложью») и роняет скрипт. Пишу `count=$((count + 1))`.
- С `pipefail` пайп вроде `cmd | head -1` может вернуть 141 (SIGPIPE), если `head` закрылся раньше, чем `cmd` дописал. Для таких мест добавляю `|| true`.
- `set -e` не заменяет проверки там, где ошибка ожидаема: их обрабатываю явно.

**Типовые приёмы обработки ошибок:**

```bash
die() { echo "Ошибка: $*" >&2; exit 1; }

command -v git >/dev/null 2>&1 || die "нужен git"      # есть ли команда
cd "$dir" || die "нет папки $dir"                       # cd может упасть
[[ -f $cfg ]] || die "нет конфига $cfg"

if ! cp "$src" "$dst"; then                             # обработать ошибку явно
  die "не удалось скопировать $src"
fi

grep -q error log.txt || true                           # ошибка допустима, не роняет скрипт

cmd1 | cmd2 | cmd3
echo "${PIPESTATUS[@]}"                                 # коды всех звеньев пайпа
```

**`trap`: прибраться при выходе.** Команда, которая выполняется при событии: выход (`EXIT`), сигналы (`INT`, `TERM`), ошибка (`ERR`).

```bash
tmp=$(mktemp -d)                                        # безопасная временная папка
cleanup() { rm -rf "$tmp"; }
trap cleanup EXIT                                       # сработает и при ошибке, и при Ctrl+C, и при exit

trap 'echo "Ошибка в строке $LINENO" >&2' ERR           # вывести место ошибки
```

`EXIT` срабатывает при любом завершении, кроме SIGKILL (его нельзя перехватить). Чтобы `ERR` срабатывал и внутри функций, добавляю `set -E`.

**Что говорю на собесе.** В начале скрипта `set -euo pipefail`, обязательные параметры проверяю через `${var:?}`, временные файлы создаю через `mktemp` и убираю через `trap ... EXIT`, ошибки печатаю в stderr и завершаюсь с ненулевым кодом, чтобы CI, cron и вызывающий скрипт узнали о сбое.

## 9. Массивы

**Как я это понимаю.** Массив это список значений под одним именем. Нужен, когда элементов много и в них могут быть пробелы (имена файлов, аргументы команды).

```bash
arr=(alpha "beta gamma" delta)      # элемент с пробелом
echo "${arr[0]}"                    # alpha
echo "${#arr[@]}"                   # 3 (сколько элементов)
arr+=(epsilon)                      # добавить
echo "${arr[@]:1:2}"                # срез: с 1-го, два элемента

for item in "${arr[@]}"; do         # обход (кавычки сохраняют пробелы внутри элементов)
  echo "$item"
done
```

`"${arr[@]}"` раскрывается в отдельные элементы, а `"${arr[*]}"` в одну строку. Для обхода всегда `"${arr[@]}"`.

**Ассоциативные массивы** (ключ и значение, нужен bash 4 и новее; на macOS по умолчанию bash 3.2, там их нет):

```bash
declare -A cfg=([host]=localhost [port]=5432)
cfg[user]=app
echo "${cfg[host]}"
for key in "${!cfg[@]}"; do         # ключи
  echo "$key = ${cfg[$key]}"
done
```

Массив удобно использовать для сборки команды с опциями: `args=(-a -v); [[ $dry ]] && args+=(--dry-run); rsync "${args[@]}" src/ dst/`.

## 10. Работа с текстом

**Как я это понимаю.** В DevOps большая часть bash это разбор вывода команд и логов: найти, отфильтровать, посчитать, заменить. Каждый инструмент делает одно, а пайп (`|`) их соединяет.

| Инструмент | Для чего | Пример |
|---|---|---|
| `grep` | Найти строки (`-i` без регистра, `-v` исключить, `-c` посчитать, `-n` с номерами, `-r` по папке, `-E` расширенная регулярка, `-o` только совпадение, `-q` без вывода, только код) | `grep -E "ERROR\|WARN" app.log` |
| `sed` | Править потоком (заменить, удалить, вывести диапазон) | `sed 's/старое/новое/g' f`, `sed -n '10,20p' f`, `sed '/^#/d' f`, `sed -i 's/a/b/' f` (правка на месте) |
| `awk` | Колонки и вычисления | `awk '{print $1}' f`, `awk -F: '{print $1}' /etc/passwd`, `awk '$3 > 1000' f`, `awk '{s+=$1} END {print s}' f` |
| `cut` | Вырезать колонку по разделителю | `cut -d: -f1 /etc/passwd` |
| `sort`, `uniq` | Отсортировать, свернуть повторы (`uniq -c` считает, вход должен быть отсортирован) | `sort \| uniq -c \| sort -rn` |
| `tr` | Заменить или удалить символы | `tr -d '\r' < win.txt`, `tr 'a-z' 'A-Z'` |
| `head`, `tail` | Начало и конец (`tail -f` следить за файлом) | `tail -n 100 app.log` |
| `wc` | Посчитать строки (`-l`), слова, байты | `grep -c ERROR app.log` или `... \| wc -l` |
| `xargs` | Превратить вывод в аргументы команды (`-P 4` параллельно) | `find . -name '*.tmp' -print0 \| xargs -0 rm` |
| `find` | Найти файлы | `find /var/log -name '*.log' -mtime +7 -delete` |
| `tee` | Писать и в файл, и дальше по пайпу | `cmd \| tee out.txt` |
| `jq` | Разбор JSON | `curl -s url \| jq -r '.name'` |

Рабочие примеры:

```bash
grep -c ERROR app.log                                  # сколько ошибок
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10     # топ-10 IP
find . -name '*.log' -mtime +7 -exec gzip {} +         # сжать старые логи
for f in *.txt; do mv -- "$f" "${f%.txt}.md"; done      # сменить расширение у всех файлов
ps aux --sort=-%mem | head -5                          # кто ест память
printf '%s\n' "$var"                                   # безопасный вывод переменной
```

**`printf` лучше `echo`:** `echo` по-разному ведёт себя с `-e`, `-n` и обратными слэшами в разных системах, а `printf` одинаков. `printf '%-10s %5d\n' "$name" "$n"` ещё и форматирует колонки.

**Имена файлов с пробелами:** `find ... -print0 | xargs -0` и циклы `for f in *` работают с ними, а `for f in $(ls)` и `xargs` без `-0` нет.

## 11. Перенаправления и процессы в скриптах

Основы потоков (`>`, `>>`, `2>&1`, `|`, `/dev/null`) подробно в конспекте по Linux. Здесь то, что нужно именно в скриптах.

```bash
exec > >(tee -a "$LOG") 2>&1        # весь вывод скрипта и на экран, и в лог (подстановка процесса)
./script.sh 2>&1 | tee -a run.log   # то же снаружи, без хитростей
cmd > /dev/null 2>&1                # молча, без вывода
cmd &>/dev/null                     # то же короче (bash)
```

**Фоновые процессы и параллельность:**

```bash
long_task & pid=$!                  # запустить в фоне, запомнить PID
other_task &
wait                                # дождаться всех фоновых
wait "$pid"; echo "код: $?"         # дождаться конкретного и получить его код

printf '%s\n' a b c d | xargs -P 4 -n 1 ./process.sh   # до 4 параллельно
timeout 10 curl -s url              # оборвать через 10 секунд (код 124)
```

**Подоболочка `( ... )` и группа `{ ...; }`:** `( cd /tmp && ls )` выполняется в отдельном процессе, поэтому `cd` и переменные не влияют на основной скрипт. `{ cmd1; cmd2; }` выполняется в текущей оболочке (нужны `;` и пробелы у скобок), удобно для общего перенаправления: `{ echo a; echo b; } > out.txt`.

**Не запускать два экземпляра одного скрипта** (пересечение запусков по cron) через `flock`:

```bash
exec 200>/tmp/myjob.lock            # открыть файл блокировки под дескриптором 200
flock -n 200 || { echo "уже запущен" >&2; exit 1; }
```

или в crontab: `flock -n /tmp/myjob.lock /opt/scripts/myjob.sh`.

## 12. Отладка и качество скриптов

```bash
bash -n script.sh                   # проверить синтаксис без запуска
bash -x script.sh                   # печатать каждую команду перед выполнением
set -x ... set +x                   # включить трассировку только на участке
PS4='+ ${BASH_SOURCE}:${LINENO}: '  # формат трассировки: файл и номер строки
shellcheck script.sh                # статический анализатор (apt install shellcheck)
```

**shellcheck** находит типичные ошибки: переменные без кавычек, `cd` без проверки, `for f in $(ls)`, `local x=$(cmd)`. Для серьёзных скриптов это обязательная привычка.

**Правила, которых держусь:**

- `#!/usr/bin/env bash` и `set -euo pipefail` в начале.
- Переменные в двойных кавычках, условия через `[[ ]]`, подстановка команд через `$(...)`.
- Переменные в функциях объявляю через `local`, константы через `readonly`.
- Ошибки пишу в stderr (`>&2`), успех и данные в stdout.
- Проверяю аргументы и наличие нужных команд заранее, а не падаю на середине.
- Скрипт делаю **идемпотентным**: повторный запуск не ломает результат (`mkdir -p`, `ln -sf`, проверка перед добавлением строки в файл).
- Не использую `sudo` внутри скрипта без необходимости, секреты не пишу в код и не печатаю.
- Скрипты пишу и храню в Linux, а не на диске Windows (иначе окончания строк CRLF ломают `#!/bin/bash`; лечится `dos2unix` или `sed -i 's/\r$//'`).

## 13. Приёмы для DevOps-скриптов

```bash
# нужен ли root
[[ $EUID -eq 0 ]] || { echo "нужен root" >&2; exit 1; }

# папка самого скрипта (чтобы не зависеть от того, откуда запущен)
SCRIPT_DIR=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)

# обязательная переменная окружения и значение по умолчанию
: "${API_TOKEN:?Не задан API_TOKEN}"
LOG_DIR=${LOG_DIR:-/var/log/myapp}

# подключить файл с настройками
source "$SCRIPT_DIR/config.env"

# дата для имён файлов и логов
stamp=$(date +%F_%H-%M)               # 2026-11-09_21-30
echo "$(date '+%F %T') старт"

# идемпотентно добавить строку в файл
grep -qxF 'export FOO=1' ~/.bashrc || echo 'export FOO=1' >> ~/.bashrc

# записать в файл, который требует sudo (sudo echo > файл не сработает: перенаправление делает мой shell)
echo "строка" | sudo tee -a /etc/some.conf >/dev/null
```

**Скрипты для cron.** Окружение у cron пустое: короткий `PATH`, нет терминала, нет моих переменных. Поэтому:

- пишу **полные пути** к командам и файлам (или задаю `PATH` в начале скрипта);
- перенаправляю вывод в лог (`>> /var/log/job.log 2>&1`), иначе ошибки пропадут;
- защищаюсь от пересечения запусков (`flock`);
- в crontab символ `%` нужно экранировать (`\%`), иначе он считается переводом строки;
- проверяю скрипт руками тем же способом, как его запустит cron (`env -i bash -c ...`).

## 14. Готовые примеры скриптов

**Бэкап папки с ротацией:**

```bash
#!/usr/bin/env bash
set -euo pipefail

usage() { echo "Использование: $0 <папка> [<куда>]" >&2; exit 2; }

[[ $# -ge 1 ]] || usage
src=$1
dest=${2:-$HOME/backups}
[[ -d $src ]] || { echo "Нет папки: $src" >&2; exit 1; }

mkdir -p "$dest"
stamp=$(date +%F_%H-%M)
archive="$dest/$(basename "$src")_$stamp.tar.gz"

tar -czf "$archive" -C "$(dirname "$src")" "$(basename "$src")"
echo "$(date '+%F %T') OK $archive" >> "$dest/backup.log"
find "$dest" -name '*.tar.gz' -mtime +7 -delete        # удалить архивы старше 7 дней
echo "Готово: $archive"
```

**Проверка доступности сайта с повторами (retry):**

```bash
#!/usr/bin/env bash
set -euo pipefail

url=${1:?Использование: $0 URL [попыток]}
attempts=${2:-5}

for ((i = 1; i <= attempts; i++)); do
  code=$(curl -s -o /dev/null -w '%{http_code}' --max-time 5 "$url" || true)
  if [[ $code == 200 ]]; then
    echo "OK (попытка $i)"
    exit 0
  fi
  echo "Попытка $i/$attempts: код ${code:-нет ответа}" >&2
  sleep $((i * 2))                                      # пауза растёт с каждой попыткой
done

echo "Сервис недоступен: $url" >&2
exit 1
```

**Разбор лога nginx (топ IP и коды ответов):**

```bash
#!/usr/bin/env bash
set -uo pipefail

log=${1:?Использование: $0 access.log}

echo "Топ-10 IP:"
awk '{print $1}' "$log" | sort | uniq -c | sort -rn | head -10 || true   # || true из-за SIGPIPE от head

echo "Коды ответов:"
awk '{print $9}' "$log" | sort | uniq -c | sort -rn
```

Поля `$1` (IP) и `$9` (код) верны для стандартного формата `combined` в nginx; на другом формате номера колонок нужно проверить.

## 15. Мои грабли и частые ошибки в ответах

- **Переменная без кавычек** (`rm $file`) ломается на пробелах и `*`. Всегда `"$file"`.
- **Пробелы вокруг `=`** (`a = 5`): bash ищет команду `a`. Должно быть `a=5`.
- **`for f in $(ls)`** ломается на пробелах в именах. Использую `for f in *`.
- **`cd` без проверки:** при ошибке скрипт продолжит в другой папке и может удалить не то. Пишу `cd "$dir" || exit 1`.
- **`rm -rf "$dir/"`** при пустой `dir` превращается в `rm -rf /`. Защита: `set -u` и `${dir:?}`.
- **`cat file | while read ...`** выполняет цикл в подоболочке, и изменённые там переменные не видны после него. Пишу `while read ...; done < file`.
- **`[ $a == $b ]`** с пустой переменной даёт ошибку, в `[ ]` нужны кавычки, лучше `[[ ]]`.
- **`cmd && echo ok || echo fail`** не равно `if/else`: `fail` напечатается и тогда, когда упадёт `echo ok`.
- **`sudo echo x > /etc/file`**: `sudo` повышает права только `echo`, а перенаправление делает мой shell без прав. Использую `echo x \| sudo tee /etc/file`.
- **`local x=$(cmd)`** прячет код возврата `cmd`. Объявляю отдельно: `local x; x=$(cmd)`.
- **`(( i++ ))` при `i=0`** возвращает 1 и под `set -e` роняет скрипт.
- **Скрипт, созданный в Windows,** падает с `bad interpreter` (CRLF в первой строке): `dos2unix`.
- **`#!/bin/sh` с bash-синтаксисом** (`[[ ]]`, массивы) в Debian упадёт: там dash.
- **Числа сравниваются как строки** через `>` в `[[ ]]`. Для чисел `-gt` или `(( ))`.
- **Дробные числа** bash не умеет, нужен `awk` или `bc`.
- **Псевдонимы** (alias) в скриптах не работают, нужны функции.
